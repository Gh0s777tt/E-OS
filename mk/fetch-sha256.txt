# SHA256 pins for the prebuilt Redox toolchain archives that mk/prefix.mk
# downloads from static.redox-os.org (U-118). The compilers that build the whole
# OS must not rest on TLS alone — a pinned digest turns a swapped artifact
# (compromised host, MITM behind a TLS terminator) into a hard build failure.
#
# Format:  <sha256>  <HOST_TARGET>/<TARGET>/<filename>
# Semantics (see the $(PREFIX)/%.tar.gz rule in mk/prefix.mk):
#   * pin present + match     -> build continues
#   * pin present + MISMATCH  -> hard fail (partial download deleted)
#   * pin absent              -> loud warning; hard fail only with EOS_STRICT_FETCH=1
#     (absent-pin combos stay soft so exotic HOST/TARGET combos don't brick)
#
# These URLs are UNVERSIONED "latest" artifacts: when upstream Redox refreshes
# the toolchain, the pinned hash goes stale and the build fails LOUDLY. That is
# working as intended — verify the refresh is legitimate (upstream announcement,
# rebuilt from a second network), then re-pin:
#   curl -sfL https://static.redox-os.org/toolchain/<host>/<target>/<file> | sha256sum
# and record the bump in CHANGELOG.md.
#
# Pinned 2026-08-14 (U-118): TOFU snapshot of the then-current toolchain; the
# x86_64/x86_64 gcc pin was re-confirmed by a second independent download during
# the live gate test (same network). A re-check from a different network / the
# build rig is a welcome follow-up; a mismatch it finds means either an upstream
# refresh or something worth investigating.
