tokens, no private keys (`keys/` holds only the public minisign key; `*.key` is
gitignored), no embedded credentials (scripts take tokens from env only), CI
uses masked variables, SBOMs clean.

## 4. Supply chain — the honest inventory

These patterns are inherited 1:1 from upstream Redox and are *why-documented*
here so nobody mistakes them for oversights. None is exploitable without
compromising TLS or an upstream release channel, but for a distribution that
advertises hardening they are the weakest links, in priority order:

1. **Prebuilt toolchain without checksums** (`mk/prefix.mk`, default
   `PREFIX_BINARY=1`). **FIXED (U-118)** — all 12 host×target×archive combos
   are SHA256-pinned in `mk/fetch-sha256.txt`; pin mismatch hard-fails the
   build (verified live: real download passed, a tampered pin was refused),
   unpinned combos warn (`EOS_STRICT_FETCH=1` upgrades to fail). The
   experimental `PREFIX_USE_UPSTREAM_RUST_COMPILER` path now verifies every
   rust-dist tarball against Rust's published `.sha256` sidecars.
2. **Build-container bootstrap** (`podman/rustinstall.sh`). **FIXED (U-118)** —
   `curl | sh` is gone: rustup installs from a *versioned* `rustup-init`
   (pins cross-checked against Rust's published sidecar hashes), and
   `sccache`/`just`/`cbindgen` are SHA256-pinned for both container arches.
   End-to-end verified in a clean Debian container (4/4 pins OK, tools run).
3. **CI helper binaries** (`.gitlab-ci.yml`). **FIXED (U-118)** — `cargo-deny`,
   `mdbook`, `mdbook-mermaid` now download-verify-extract against pinned
   SHA256s (no more `curl | tar xz`).
4. **Unsigned-publish is warn-only**. **FIXED (U-120)** — missing signing key
   now hard-fails `publish-repo-pages.sh` / `publish-repo.sh` /
   `make-release.sh`; dev flows must opt in explicitly with
   `EOS_ALLOW_UNSIGNED=1`.
5. **u-boot firmware blobs** from a developer's personal namespace
   (`mk/qemu.mk`, RPi/uboot targets only) — **OPEN**: pin checksums when that
   target is next exercised.
6. **`eos-repo-sign keygen`**. **FIXED (U-119)** — the secret key is created
   `0600` on Unix via `create_new` (atomic, no world-readable window) and an
   existing key file is never clobbered; regression-tested (CI-identical
   container run, 9/9 tests).
7. Container gets `--network=host` (`mk/podman.mk`) — **OPEN** (documented
   trade-off); revisit if recipe count grows.

Minor correctness notes filed for whenever those files are next touched:
`native_bootstrap.sh` `redox()` iterates an undefined `$PKGS` (never installs),
`mk/prefix.mk:286` has a broken `rm … && dir && exit 1` error path,
`scripts/cargo-update.sh` can `cargo update` the repo root if the recipe path
is missing, `scripts/eos-check.sh` interpolates its argument into a
`bash -lc` string (quote-injection; owner-run dev tool, low risk).

## 7. Verification method

Everything above is grounded in primary evidence: `git ls-remote` comparisons
across all 60 remote endpoints, the failing jobs' raw CI traces, byte-level
diffs of the local tree against HEAD `763c874`, and file reads — followed by an
independent adversarial-verification pass that attempted to refute each
significant finding (two *were* refuted and are recorded above as deliberate,
not leaks). Where a fix could not pass the §1 Definition-of-Done gates
(build + boot-smoke) because the build container is down, the change was
either deferred (pin bumps) or is docs/CI-metadata-only.
